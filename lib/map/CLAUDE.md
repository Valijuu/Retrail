# Map & previews (the key improvement)

> Keep this file in sync with the actual code — update it as part of the same change whenever something documented here changes.

- **Live/active-ride map:** native **MapLibre** (`maplibre` package, pinned `^0.3.6` — bumped from `0.2.2` specifically to pick up an upstream Android fix for a native disposal crash, issue #16) with an OpenFreeMap vector style (Spec 19): the bundled **Retrail Light** (`assets/map/retrail_light.json`, Liberty toned down) / **Retrail Dark** (`assets/map/retrail_dark.json`, OpenFreeMap Dark recoloured onto the app's dark terrain) — `liveMapStyle(dark)` hands MapLibre the asset path, which it loads itself asynchronously. Never a JSON string: MapLibre applies that synchronously, before `onMapCreated`, whose `_detachMap()` then discards the loaded style and the placeholder never lifts (found on the device). Route, endpoint markers and the current-position marker are GeoJSON source layers: halo (white, wider) + blue line on top, with blue, white-rimmed direction arrowheads placed along it by MapLibre (`symbol-placement: line`); the camera follows the current position **heading-up** — rotated to the travel direction, advanced by `nextHeading` (`lib/domain/heading.dart`) from **recorded** (GPS-filtered) points only, re-measured every ≥ 10 m and ignoring turns < 10° so GPS noise doesn't swing it — and drops follow on a user gesture (pan / zoom / rotate), keeping its rotation; the very first position (no fix and no route yet — the map still sits at its (0,0) init center, e.g. the first ride after install) is an instant jump at ride zoom, never an animated fly (`followCameraUpdate`'s `instant`) — every instant jump goes through `_jumpCamera` (move, then zoom at the new centre: iOS' `moveCamera` otherwise applies the zoom at the old centre's latitude and lands short, #41); every follow / recenter move requests ride zoom (`initialZoom`), never `controller.camera.zoom` — any zoom gesture drops follow anyway, and mid-flight iOS reports the fly-to arc's zoomed-out value, which would otherwise stick (#40); a `MapCompass` (bottom-left, stacked right above the recenter button via `LiveMap.compassClearance`; app-token face like the recenter FAB) then shows while the map isn't north-up (tap → north), and the recenter control reinstates heading-up follow. The live line's tip follows the gliding position marker: the `route` source stops one fix short and a `route-tail` segment runs from there to the marker's drawn position, updated with each glide frame (`splitRouteTail`); a fix arriving mid-glide first lands the marker on the previous target so the line never runs ahead. The route itself is only re-pushed when a point was added. The read-only detail / fullscreen map (`fitBounds: true`) has no tail and **no compass** (it opens north-up; two-finger rotate still works). It frames the whole route with `fitRouteCamera` (`lib/map/route_camera.dart`: bbox centre + fractional zoom for MapLibre's 512-px world, 24 px padding, capped at `maxPreviewZoom`), used as its init camera and applied with one instant move after style load — **not** the package's `fitBounds()`: on iOS that only starts an animation and returns, so the old zoom-cap `moveCamera` right after it cancelled the fit and left the camera on the route's end. It re-frames (north-up) whenever its size changes: the detail dialog moves the SAME map — one `GlobalKey` — into fullscreen and back, so fullscreen starts no second native map. Until the style has loaded, its placeholder is a `RouteSketch` projected with that same camera (`cameraOffsets`, map line widths, markers ×`mapEndpointMarkerScale`, no arrows — MapLibre's own can't be matched); it also covers the resize when fullscreen toggles. So the route shows at once, cross-fades into the map without a jump, and stays visible offline when no style is cached. A light/dark switch rebuilds the native map (`ValueKey(dark)`); `didChangeDependencies` detaches the old one at once (`_detachMap`: no controller/style/sources) so no camera move or source update in between reaches the disposed map (#43). A style load that was overtaken meanwhile (detached, or a newer style loaded) bails out after every await in `_onStyleLoaded` and its helpers (`_superseded`), so it never adds layers to the dead map or sets the ready flags against the new style (#47). When following a saved route (Spec 17/18), `LiveMap.reference` is the route **as ridden** (`RouteFollowState.orientedTrack`, reversed after a flip) and adds a `reference` / `reference-done` source pair *under* the live line: `reference` holds the whole route in halo + blue with arrows, `reference-done` the ridden parts (`referenceDone` = `RouteFollowState.ridden`, one segment per ridden part — a shortcut starts a new part, a part on a loop ridden across its seam splits in two — drawn by `referenceGeoJson` as one MultiLineString, segments < 2 points dropped) in `onSurfaceVariant` on top of it, all at `kReferenceRouteOpacity`, plus its start/finish markers (`ref-start` / `ref-end`) below the current marker. The map never cuts at `progress.alongM` (non-monotonic after a finished loop lap). Its pushes are gated on `_sourcesReady` like every other source and, via `referencePushTarget`, on this style load having created the reference sources (`_drawnReference`); the whole `reference` line is pushed only when the reference itself changes (`referenceUpdateGeoJson` against `_lastPushedReference`, which shares `_drawnReference`'s lifecycle), so a growing ridden part pushes only `reference-done`; a replaced reference (a flip) also moves the marker points (`referenceMarkerPoints`), but only the marker sources this style load created (`_drawnReferenceMarkers`: the endpoint style drawn then + the reference they show — the catch-up push after style load moves them if a flip landed mid-load). A brightness rebuild redraws everything from the current (oriented) props. A reference that appears later is drawn from the next style load on, and the live placeholder becomes a `RouteSketch` of it. `headingTrail` (follow-only screen, no line of its own) replaces `points` as the heading-up input. With both null the live map is unchanged. Positions passed to the package (camera center) are `Geographic(lon:, lat:)` (the package migrated from `geotypes`' generic `Position` to `geobase`'s `Geographic` in 0.3.0).
- **Map credit:** the OpenMapTiles (CC BY) and OSM licences require a credit on every map, but the `maplibre` package hides the native attribution control on Android (`attributionEnabled(false)`) and iOS (`showsAttributionButton = false`). `MapAttribution` (`lib/map/map_attribution.dart`, ARB `mapAttributionOpenMapTiles` / `mapAttributionOsm`: "© OpenMapTiles © OpenStreetMap", same in EN and DE) draws it instead: bottom centre of the ride / follow map (`RideMapArea`, between the corner controls, hidden while `masked`) and of the detail + fullscreen map, tappable (`onOpen: openMapCopyright` → the pages in `MapConfig`); it always stays written out (no collapsing — decided 2026-10-06). Bottom left of a history card's preview as plain text (the thumbnail is the card's tap target).
- **Android platform-view mode: texture-based** (`androidTextureMode: true`, `androidMode: AndroidPlatformViewMode.tlhc_vd` in `lib/map/live_map.dart`). Hybrid Composition (the smoother default for panning) rendered the map via its own independent native Surface; on a real device that surface could get recomposited mid-transition and flash a stale buffer from an unrelated earlier screen — reproduced as the countdown page flashing for one frame when leaving `/ride` (issue #11). Texture mode routes the map's output through Flutter's own frame instead, at some cost to pan/gesture smoothness. Revisit if that cost turns out to matter more than the flicker did.
- **Ride previews (history):** rendered **once at ride-save** — `OpenFreeMapTileProvider` (`lib/map/openfreemap_tile_provider.dart`, Spec 19) draws OpenFreeMap vector tiles for the route's framing (Web Mercator bounds, zoom capped at `maxPreviewZoom = 16`): TileJSON `tiles.openfreemap.org/planet` → versioned tile URL (re-resolved after a 404, the weekly data rotation), z > 14 drawn from the z14 parent (`overzoomTile`), pbf parsed on a background isolate, painted with `vector_tile_renderer` in the same bundled Retrail Light / Retrail Dark style minus `raster` and `fill-extrusion` layers (labels stay, device font), 768 px per 256 dp tile; parsed tiles are kept in a small LRU so rides in one area share them; every request sends `User-Agent: Retrail (io.github.valijuu.retrail)`. The halo+blue polyline is painted on top and the result exported to a **disk-cached PNG** keyed by `rideId` + brightness. Both theme variants are rendered — the active one first, the other right behind it (at ride-save and in the history pre-warm) — so a light/dark switch finds every preview ready instead of re-rendering the list. Lists show `Image.file(...)` → no tiles, no network, no GL during scroll.
- **Route markers (everywhere a route is drawn — preview PNG, offline sketch, `RouteSketch`, detail/fullscreen map):** start = hollow green ring, finish = chequered flag disc (`scrim`/`onMap`), and when start and finish are ≤ 30 m apart (a loop) one combined marker (chequer inside the green ring) instead of two stacked ones — the decision is `routeEndpointStyle` in `lib/domain/route_markers.dart`. Direction arrowheads every `routeArrowSpacing` along the line — the line's own blue with its white halo as a rim, about twice the line's width, kept clear of the markers (`directionArrows`). All canvas drawing lives in `lib/map/route_marker_painter.dart`; the map rasterises the same markers/arrowhead to PNG symbol images at the device pixel ratio.
- **Preview cache versioning:** PNGs live in `ride_previews_v<N>` (`_cacheVersion` in `route_preview_cache.dart`); bump N whenever every cached preview must re-render (pixel ratio, marker/arrow look, …). `purgeOutdatedVersions()` (called once from `main()`) deletes older `ride_previews_v*` directories.
- **Offline at save-time:** store a flat `RouteSketch` PNG (polyline over `AppColors.mapTerrain`), mark stale, regenerate full-tile snapshot when back online. Evict the cached image on ride edit/delete.
- Port projection math verbatim with its tests: `lonXAtZoom`, `latYAtZoom`, `latYFrac`, `projectPoint`, `computeFraming`, zoom cap, degenerate-bbox handling.

## Offline behavior

GPS recording and ride saving are **fully local — no internet required**. Only map *tiles* need the network. In flight mode: recording continues, the route polyline still draws, an offline banner shows, the ride saves with a flat preview that regenerates later. `ConnectivityObserver` uses an active HTTP `generate_204` probe (NOT the OS "validated" flag, which some VPNs fake), polled every 10s + on network change.
